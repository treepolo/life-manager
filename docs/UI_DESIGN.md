# UI與資訊視覺化規範

## 1. 設計方向

### UI-001　淺色優先

第一批主要主題為淺色。不能因為想做遊戲感、科技感便自動使用深色、霓虹、賽博背景或發光HUD。

### UI-002　明顯遊戲介面感，但不幼稚

遊戲感來自：

- 領域、事業、任務、狀態、成果及長期進度的結構；
- 今日行動的優先節奏；
- 清楚的狀態改變與完成回饋；
- 從總覽進入領域、事件、資料與計算依據的探索層級；
- 每個領域／事業可辨識的視覺身分；
- 版面構圖、比例、邊界、導覽與互動節奏。

禁止用吉祥物、金幣、寶箱、每日簽到、無意義XP、幼稚徽章、廉價升級動畫或健康App式打卡製造遊戲感。

### UI-003　科技、克制、部分硬派／粗獷

介面可以具有科技感、極簡克制、硬邊界、清楚網格及部分brutalist特徵，但不能硬套軍事、交易終端、戰機、賽博HUD或任何既有模板。視覺必須為本產品的資訊結構服務。

### UI-004　帥與有趣來自設計，不是裝飾

不依靠大漸層、玻璃模糊、發光線、過多圖示或花俏動畫。以字體層級、版面比例、狀態色、細節、微互動、資料轉場及非對稱但有秩序的構圖建立個性。

## 2. 資訊密度與層級

### UI-005　三層資訊

1. **一目了然層**：今日行動、超級重要期限、少量關鍵狀態。
2. **綜觀大局層**：各領域、事業、財務、社群及長期趨勢。
3. **深入分析層**：高資訊量表格、篩選、圖表設定、原始資料及計算依據。

不同層級可以有不同密度。分析頁可高密度但需分組、對齊、留白及視覺導引；不得把所有頁面都做成緊繃表格，也不得用大卡片和大片空白稀釋資訊。

### UI-006　版面尺度

- Body文字以可長時間閱讀的正常尺寸為主，不使用大字湊版。
- 區塊間距緊湊但可辨識。
- 容器以小圓角、直角、分隔線、底色帶、表格與網格混用。
- 不能把每項資訊都包成同尺寸白色大圓角卡片。
- 版本更新、同步衝突等需要立即處理的全域提示必須固定在初始viewport內；手機版須避開底部同步狀態與導覽，不得把提示排在長頁面內容之後。
- 重要資料不藏在多層選單；進階設定可折疊，但定義與來源必須易於找到。

## 3. 首頁

首頁由上而下：

1. **今日行動中心**：最上方且可直接操作。
2. **超重要期限警告**：若有啟動事項，立即佔據明顯位置；`SUPER_CRITICAL`可阻礙式顯示。
3. **當前狀態與同步狀態**：待同步筆數、外部provider錯誤、資料更新時間。
4. **人生領域／事業總覽**：每個領域顯示可控行動、系統條件、能力累積及結果，不以單一分數取代。
5. **財務與社群關鍵趨勢**。
6. **最近事件與快速入口**。

今日行動最重要，但其他三種首頁角色（總控、角色／人生面板、整體總覽）都需完整存在，不得因置頂任務而省略。

## 4. 導覽與手機版

- 桌面使用固定但不臃腫的主導覽，顯示模組與目前事業／領域脈絡。
- 手機使用底部或易單手操作的主要導覽，今日、總覽、記錄、分析、更多需明確。
- 手機版優先顯示操作與警告；深度表格可切換摘要／完整，但不能刪除必要欄位。
- 不允許將桌面所有卡片直線堆成無止盡長頁。
- 所有互動目標符合觸控尺寸，表格必要時使用欄位選擇與局部橫向捲動。

## 5. 元件規則

### 容器

- 預設小圓角或直角。
- 陰影少用，優先邊線、底色與層級。
- 同一頁不能有十幾個視覺相同的卡片。
- 關鍵區可使用整面色帶、粗邊界、編號及狀態標記。

### 按鈕

- 主要行動明顯，次要動作克制。
- 不使用滿頁藥丸按鈕。
- 完成任務與標記期限完成需有清楚確認及可復原策略。

### 動畫

- 用於狀態變化、完成回饋、圖表過渡及層級切換。
- 不阻礙操作、不拖慢輸入、不用彈跳或煙火製造幼稚遊戲感。
- 支援`prefers-reduced-motion`。

## 6. 禁止的常見AI美學

- 超大圓角卡片；
- Notion模板；
- 通用SaaS dashboard模板；
- 健康App／習慣養成App；
- 字太大、區塊太鬆；
- 大片無資訊意義留白；
- 軟綿、玩具化圖表；
- 重要資訊藏太深；
- 大量馬卡龍色、玻璃感、無意義漸層；
- 只用Lucide圖示加文字便當成設計；
- 每個模組各自生成不同風格；
- 預設元件庫未調整便直接交付。

## 7. 圖表規範

### UI-CHART-001　完整標題

每張圖有具體圖名與必要副標，說明比較對象、時間範圍及資料性質。

### UI-CHART-002　軸名與單位

所有數值軸必須有軸名及單位；時間軸顯示時區／粒度。若不需顯示軸的圖表類型，仍需在圖例或標籤明示單位。

### UI-CHART-003　刻度

刻度間距須符合數據尺度，不得隨意截斷或產生誤導。預設從零是否適用需依圖表類型決定並可明示。日期刻度不能與資料粒度不一致。

### UI-CHART-004　圖例與系列

多系列均有完整名稱；相近顏色需搭配線型、點型或直接標籤。不得只靠顏色傳達狀態。

### UI-CHART-005　完整tooltip

顯示完整時間、精確值、單位、系列、事件及必要來源；軸上可縮寫，但tooltip可查看未縮寫數值。

### UI-CHART-006　資料定義

圖表附近可查看：

- 累積／區間／平均／總和／比例；
- 分子與分母；
- 樣本數；
- 缺失與排除；
- 資料來源；
- 最後更新；
- 公式版本；
- 精確／近似／估算品質。

### UI-CHART-007　設定

依圖表提供相關設定：

- 日期範圍；
- 粒度；
- 聚合；
- 系列；
- 篩選；
- 分組；
- 原幣／TWD；
- 事件overlay；
- 累積／非累積；
- 顯示零值／缺失值；
- 精度；
- 儲存視圖。

不能把所有設定硬塞給每張圖，但相關控制必須充分。

### UI-CHART-008　不同量綱

不同量綱原則上分圖。需要雙軸時，兩軸名稱、單位、顏色及尺度必須明確，並顯示警告避免誤讀。

### UI-CHART-009　事件標註

事件釘在正確時間，支援篩選、hover及點擊查看。事件密集時需要聚合或分層，不得遮住曲線與刻度。

### UI-CHART-010　可驗證性

圖表數字必須能連到資料表／計算依據。Playwright需驗證軸名、單位、圖例、設定及資料更新後曲線／數字改變。

## 8. 視覺驗收方式

Codex先建立共用設計token及四個代表頁面的正式高完成度實作：

- 首頁；
- 財務分析；
- 社群分析；
- 超重要期限警告。

代表頁面使用`tests/fixtures`或本機開發seed驗證資訊密度，但正式production build不得引用fixtures。完成這四頁後再套用至其他頁面，不能每頁自行生成風格。

視覺驗收需涵蓋320px手機、一般手機、平板、1366px筆電與大型桌面；不得只在寬螢幕截圖看起來正常。
